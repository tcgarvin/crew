# Ship Life: Implementation Plan

Status: plan, 2026-10-04. Design and rationale: `docs/design/ship-life.md` (section references
below are to that file unless marked Dockside). Five slices, as §12. Each slice ends deployed,
with all checks green (`pnpm typecheck && pnpm lint && pnpm depcruise && pnpm test`), a phone
playtest, and a pause to take stock. Slices 1 and 2 are planned in full below; slices 3–5 are
sequenced and will be refined after the slice before them lands. Each slice adds its own
`D<n>` entries. Slice 2 was planned on 2026-10-04 after slice 1 landed (D72–D74).

Slice 1 is built by one serial *contract gate* followed by parallel workstreams in separate
worktrees. The gate changes every shared type and leaves the repo green; each workstream then owns
a disjoint set of files. Shared files are named with their owner.

## Slice 1: Freighter Mk2, hull contract, berth boxes, bow east

Scope (§12.1): the `hull` block and its invariants; the `hullContract` validator pass; dock maps
on `berth` boxes with the six maps re-authored; the renderer flipped to bow-east; Mk1 mirrored and
kept loadable; the Mk2 deck with every room and piece of furniture placed, mostly inert; berth
assignment and lockers; the ninth crew member. Save schema 6 → 7. Behaviour is otherwise
unchanged: nobody cooks, no watches, no dirt.

### Calls made

Where the design is silent or does not fit the code, the plan decides; each is one line.

1. **`hull` carries no `rampSlots`.** The ramp tiles are already the ramp doors' edges
   (`docking.*RampDoorKey`); a copy would drift. The validator checks the doors instead.
2. **Orientation is checked as: the `bridge` compartment touches the east hull edge, and both
   ramp doors are on side `s`.** The sim has no direction, so "bow east" has to be read off the
   layout.
3. **`DockDef.shipAt` goes; the ship's place is derived.** `berthPlacement(dock, deck)` in
   `core/docks.ts` puts the ship flush to the box's south edge and centred, so every reader is
   found by the compiler and two footprints share one rule.
4. **The Mk1 mirror and the dock-map conversion run in the gate**, not as workstreams: until both
   are done the authored bundle fails the new rules, and every stream's tests load it.
5. **`machine.bridge_console` becomes `machine.helm` now**, `galley` machine tag becomes `stove`,
   and the medbay bed is retagged `medBed` (no longer a sleep target, §7). The design puts the
   helm rename in slice 2; authoring Mk2 against a name that changes next slice is worse.
6. **Berth assignment is a standing rule, not a one-off:** any crew member or passenger without
   a berth gets the first free bed that fits their rank, every tick. That covers scenario start,
   a passenger boarding, a narrator-spawned crew member and a restored save with one line.
7. **Saves older than schema 7 are refused.** Mk1's coordinates are mirrored, and the dock maps
   change shape; migrating every tile-bearing field (locations, paths, plan steps, facts, claims)
   is the "change the compiler cannot find" D59 warned about. `restore` throws
   `SaveCompatibilityError`; the host already starts a new game on that path
   (`apps/web/src/worker/host.ts`). PLAN §3 allows it before players exist.
8. **Lockers link to beds by `ZoneDef.machineKey`** (new, optional: the placement a zone serves),
   not by key convention. Personal items (`personal` item tag) in a crew member's starting
   inventory are set down in their berth's locker at scenario start; `Item.ownerId` records
   whose they are. Nobody fetches them until slice 4.
9. **Starting stores stay in `cargo_stow`.** The pantry, parts and cleaning-locker zones are
   placed but unused: crew learn item locations by looking, and nothing walks through Stores yet.
   Slice 3 moves provisions and parts there with the cook loop.
10. **`rampLandings` overrides are not built** (§10 says none of the six need them).
11. **The ninth crew member is Noor Haddad**, role `pilot`, piloting 3, shift `beta` (so one
    piloting ≥3 is on every shift: Mara and Jax alpha, Dane and Noor beta). The design uses the
    name "Noor" in its own examples.
12. **`crew content render-dock` composites every deck in the bundle**, one map per deck, so the
    README shows both footprints in each box.
13. **Dock READMEs are regenerated by the lead at integration**; no stream hand-edits them, and a
    stream whose change alters them (a new deck) may skip the staleness test locally.
14. **The two reserved bridge tiles are floor with nothing on them**, named in the deck README;
    stations arrive as content in slice 5.
15. **`grime` and `airborneDust` wait for slice 3.**
16. **The narrator prompt's "eight people" becomes "nine"** (prompt version bump); the lead runs
    `pnpm test:live` once at the end of integration.

### Gate: contracts (one agent, serial)

Everything below lands as one commit with all four checks green. Stubs are fine where behaviour
is a workstream's; types, schemas, generated schemas, scripts and the minimum content to keep the
bundle valid are not.

**Sim types (`packages/sim/src/core/types/content.ts`).**

- `HULL_SIZE_CLASSES = ["S", "M", "L"] as const`, `HullSizeClass`, and
  `HULL_SIZE_BOX: Record<HullSizeClass, { w, h }>` = S 24×14, M 36×20, L 40×24.
- `DeckDef.hull: HullDef` where `HullDef = { class: string; sizeClass: HullSizeClass }`
  (required).
- `ZoneDef.machineKey?: LocalKey`.
- `DockDef.berth: { origin: TileCoord; sizeClass: HullSizeClass }` replaces `shipAt`; the doc
  comment on `DockDef` is rewritten (tile frame, the box, the ship derived).
- `DOCK_TILE_KINDS = ["floor", "wall", "void"]` (`berth` removed).
- `MACHINE_TAGS` gains `navStation`, `opsStation`, `chair`, `desk`, `stove`, `medBed`,
  `messTable` (exists), `gamesTable`, `vidScreen`, `exerciseRig`, `workbench`, `console`, and
  loses `galley`.
- `ITEM_TAGS` gains `personal`.

**Sim state (`core/types/state.ts`, `core/types/ship.ts`, `core/types/view.ts`).**

- `WorldState.berths: Record<ActorId, LocalKey>` (bed placement key; owner: needs). Added to
  `emptyState` in `core/world.ts`.
- `UniqueItem.ownerId?: ActorId`.
- `SelfView.berth?: { machineId: MachineId }` (filled by `view/agentView.ts` from `berths` and the
  machine table; stub returning it is fine).
- `SCHEMA_VERSION = 7`, with the history line. `core/migrations.ts` gains `6:` a migration that
  throws `SaveCompatibilityError("save predates ship life (schema 6); start a new game")`
  (call 7). `core/save.ts` imports nothing new; `save.test.ts` gets one test that a schema-6
  envelope is refused and the host test (`apps/web/src/worker/host.test.ts`) that it starts a new
  game still passes.
- `core/invariants.ts`: `berthViolations` stub (every key is an actor, every value a placement key
  of a `bed`-tagged machine on the deck, no two actors share a value). The content-free
  `checkInvariants` can check keys and uniqueness; the machine check goes in a
  `systems/needs/invariants.ts` the berth stream writes.

**Berth placement (`core/docks.ts`).** `berthPlacement(dock, deck): TileCoord` =
`{ x: origin.x + floor((box.w - deck.width) / 2), y: origin.y + box.h - deck.height }`, throwing
if the deck exceeds its class box or the box its class. `dockToDeck`/`deckToDock`/`isDockFloorAt`
and everything downstream take `{ dock, shipAt }` (a `BerthedDock`) or `(dock, deck)`; the
content-only helpers (`dockForPort`, `dockAlongside`, …) that need the deck widen their `content`
pick to `"docks" | "decks"` and read the deck from `state.deck.dock.deckId`. `systems/spatial/
geometry.ts` (`gridBounds`, `dockFloorTiles`, `dockGraft.offset`), `core/locals.ts`
(`rampLandings`), `core/floor-set.ts`, `systems/travel/*` compile against the new signatures.
`packages/sim/src/index.ts` exports `berthPlacement`, `HULL_SIZE_BOX`.

**The ship's deck is the world's, not the bundle's first.** Three helpers take
`Object.values(content.decks)[0]`: `systems/travel/travel.ts` `theDeckId` (ramps, `attachDock`,
and `systems/commerce/passage.ts:93` through it), `systems/commerce/tasks.ts` `firstDeck` (haul
tiles), `systems/commerce/jobs.ts` `cargoStowageZoneKey`. With two decks they pick whichever
`loader.ts` lists first. Add `shipDeckId(state)` in `core/world.ts` (the one key of
`state.deck.tiles`; throws on none or several, as the migrations and narrator fixtures already
assume) and use it in all three.

**Content schemas (`packages/content/src/schemas/`).** `deck.ts`: `hull`, zone `machineKey`.
`dock.ts`: `berth`, tile kinds. `primitives.ts`: machine and item tag enums (the `AssertEqual`
guards force this). Regenerate `schema-json/*.json` with `crew content schemas`.
`validate-dock.ts`: `checkBerth` becomes the box check in its simplest form (box inside the map,
every box tile `void`, the deck's floor inside the box), `dockRampLandings(dock, deck)` uses
`berthPlacement`; the full rule set is the validator stream's.

**Renderer, compile-only.** `apps/web/src/render/dock.ts` (`dockOrigin`, `dockRectOnDeck`),
`camera.ts`, `dockHit.ts`, `dockShape.ts` (berth box from `dock.berth` and `HULL_SIZE_BOX`,
`runs.berth` gone, `quay` edges = box perimeter edges that meet floor), `dockArt.ts`
(`fillRuns(shape.runs.berth)` becomes a box fill), `DeckCanvas.tsx` and tests, all using
`berthPlacement(dock, deck)` from the layout's deck. No direction change here.

**CLI.** `render-dock.ts` composites every deck (one map block per deck, "docked at (x,y)" per
deck); `index.ts` drops the "exactly one deck" rule; `index.test.ts` literals follow.

**Scripts (one-off, kept under `scripts/`).**

- `scripts/mirror-deck.mts <deck.json>`: `x → width-1-x` for every tile row, door and
  opening/wall edge (side `e ↔ w`), zone tile, spawn and transfer tile; machines are re-placed
  from their mirrored absolute footprint: a def whose footprint and interaction offsets are
  symmetric in x keeps its rotation, otherwise rotation 180 (which also flips y offsets; the
  validator decides whether the result is on floor). Runs on `freighter-mk1.json`; the README is
  regenerated by `crew content render-deck` and its hand-written header says east is fore.
- `scripts/convert-dock-berth.mts <dock.json>`: `berth` legend rows become `void`; `berth:
  { origin, sizeClass: "M" }` is written so that `berthPlacement` for the 32×18 Mk1 lands where
  `shipAt` was (origin = shipAt − (2, 2)); where that puts the box above row 0, void rows are
  inserted just above the ship (hub, Kessler, Ossory, Vesper: 2; Tern's Rest: 1; Green Meridian:
  0) and every post, area, prop and foreground rect at or below the insertion shifts or grows;
  every tile inside the box becomes void and a prop inside it is dropped with a log line. Tern's
  Rest keeps its width (origin x 0, so the ship moves one tile east). Then `crew content
  render-dock` for each.

**Content, minimum to stay valid.** Mk1 (mirrored) gets `hull: { class: "light_freighter",
sizeClass: "M" }`; `machine.bridge_console` is renamed `machine.helm` (file `helm.json`, placement
key `helm_1`, a second interaction position `standby` for §2, `use`); `galley_stove.json` tag
`stove`; `medbay_bed.json` tag `medBed`; two new inert defs, `nav-terminal.json` (`navStation`)
and `mess-table.json` (`messTable`, footprint 2×1, four `seat` positions, `use`), each placed
once on Mk1 (bridge and mess) so the hull contract the validator stream enforces already holds.
Hand-built sim fixtures with a `berth` legend (`systems/spatial/fixtures/dock.ts`,
`systems/work/fixtures/crew-deck.ts`, and the travel/commerce `fixtures-dock.ts` files) get the
same conversion by hand.

**Tests the gate must fix to stay green** (literals only; the rules stay): `apps/cli/src/
index.test.ts` (hub "docked at", `personnel_ramp: (5,19)` → the mirrored landing, `decks[0]`,
and the flood test, which must flood the box rows with floor instead of relegending `B`);
`packages/content/src/schemas/validate-dock.test.ts` (`PERSONNEL_LANDING`/`CARGO_LANDING`, the
`shipAt {4,1}` message becomes a `berth.origin` one, the hub's 38×28 literals after the row
insertion); `apps/web/src/render/dock.test.ts` and `dockArt.test.ts` (`shape.berth` is the box,

localInspection.test.ts` and `placeInspection.test.ts` (hub tiles `(20,23)` and `(30,19)` move
down by the inserted rows); `camera.test.ts` legibility rerun. None are deleted.
